# Как работаем над РесурсБронью

## Ветки и коммиты

- Для каждой задачи создаём ветку от актуальной `main`. Формат — `<тип>/<номер-issue>-<краткое-имя>`. Типы — `docs`, `feat`, `fix`, `chore`. Пример — `docs/12-request-booking`.
- Коммиты пишем в формате `тип(область): действие`, например `docs(booking): описать проверку конфликтов`. Один коммит содержит одно логически связанное изменение.
- Прямой push в `main` закрыт. Все изменения попадают туда через PR. Ответственный за репозиторий проверяет, что правило защиты ветки требует хотя бы одного одобрения от другого участника.

## Pull request и review

1. Исполнитель берёт назначенный issue, создаёт ветку и открывает PR в `main`. В описании PR указывает связанный issue, изменения, затронутые сценарии и способ проверки. Добавляет `Closes #N`, если PR полностью закрывает issue.
2. Автор назначает другого участника на review. Для требований рецензент сверяет основной поток, критерии приёмки, ошибки и переходы Job. Для реализации проверяет также тесты и работу с правами и параллельными запросами.
3. Рецензент оставляет хотя бы один содержательный вопрос или замечание по конкретному месту. Пример — «Что произойдёт с бронью, если проверка завершится после дедлайна, а фоновая задача ещё не запустилась?»
4. Автор отвечает и вносит согласованные правки. Рецензент одобряет актуальную версию после проверки исправлений. Участник с правом слияния вливает PR после одобрения, закрытия обсуждений и прохождения обязательных проверок, если они настроены.
5. Для сдачи каждый участник сохраняет ссылку на свой влитый PR или на своё содержательное review чужого PR. По возможности сохраняет обе ссылки.

## Definition of Done

- У задачи есть назначенный исполнитель, а PR связан с issue.
- Результат покрывает согласованные критерии приёмки. Изменения требований согласованы с README и жизненным циклом Job.
- Для документации проверены ссылки, полнота сценариев и формулировки «Дано / Когда / Тогда». Для реализации проверены затронутые критерии приёмки, включая ошибки, и пройдены обязательные проверки проекта.
- Содержательные замечания обработаны, другой участник одобрил актуальный PR, PR влит в `main`.
- Issue закрыт, если все его критерии выполнены.
